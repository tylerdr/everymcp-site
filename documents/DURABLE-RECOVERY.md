## Implemented source

`lib/recovery/binding.ts` owns one account/mode/project binding shared by checkout, signed webhook, paid return and verified-owner recovery. `starterRecoveryEnabled = false` is a source gate: environment variables alone cannot activate it. Legacy Stripe configuration cannot open chargeable checkout. The binding requires durable store, authoritative purchase reader, account verifier, signature verifier and verified current-user identity. Missing dependencies, unsafe store privileges, failed account/store checks or absent/wrong-scoped owner refuse checkout before a session-create call. The pricing CTA also uses binding readiness.

`postgres-store.ts` uses pinned pg8.23.1, TLS certificate verification, a dedicated server login, max2connections,5sstatement/lock/connection/idle deadlines, SERIALIZABLE transactions, account/mode advisory locking and at most3attempts for serialization/deadlock/unique conflicts. It checks dedicated noninheriting/non-bypass role, forced RLS and SELECT/INSERTonly permissions on both fixed private tables, then readiness exercises actual configured account/mode INSERTs into both tables inside a rollback-only transaction (no probe committed). Grant-present but policy-denied writes refuse chargeability. These rollback-only INSERTs are database writes requiring approved sandbox write permission; they are NOT the earlier catalog-only/read-only preflight. It validates persisted event keys/hashes before map assignment and discards failed connections. It scopes every parameterized read/insert, and refuses mutation/deletion, corrupt receipt state or failed commit before acknowledgement. Fake-client tests are not actual PostgreSQL durability/concurrency proof. Catalog ACL/capacity preflight, exact RLS policy review and actual rollback/restart proof remain prerequisites.

`owner.ts` verifies only the bearer caller's or HttpOnly-cookie buyer's own current Supabase user at the fixed project Auth endpoint, requiring confirmed email and nonanonymous valid user ID. Responses are bounded64KB and requests5s. No admin/service_role/auth.users lookup. Opaque owner keys bind product/account/mode/project/userID. Checkout stamps this server principal and verified email; body/query owner/email cannot grant rights. Provider failures remain unknown503; explicit expired/denied credentials return401.

The minimal public buyer entry is now implemented, still disabled: `/buyer/sign-in` requests and verifies an email confirmation code using pinned Supabase SDK2.117.3 (`shouldCreateUser:true` provides first-time onboarding only when an approved project is activated). A verified code must also pass canonical current-user/confirmed-email checks. Session tokens are never returned in JSON or stored in browser storage: one Secure/HttpOnly/SameSite=Lax `__Host-` cookie lasts at most15minutes or the shorter token lifetime. No refresh, password/settings platform or global sign-out; browser sign-out clears only its cookie. All mutations require same-origin JSON, bounded completed bodies, and deadlines. Explicit SDK invalid/expired-code errors deny401; provider/rate-limit/unknown errors retry503 without replacing a cookie. Stalled JSON prefixes cannot invoke adapters.

Listing slug or planner goal survives pricing→sign-in→checkout; local safe return destinations allow only sanitized pricing intent or a64hex receipt selector. `/buyer/purchases` lists only canonical owner's stored receipts and supports lost-return recovery, session expiry/reverification and download retry without a second checkout. Bound-contract success pages and downloads require the current owner; ownerB cannot use ownerA's session link. Query owner IDs grant no access. Both buyer pages are dynamic/noindex and excluded from the sitemap. Checkout, Auth and recovery remain closed by the same hard source gate, before configuration/client/provider operations. UI source implementation is complete; actual Auth signup/mail policy and hosted resource proof are not approved or performed.
