# Disabled durable receipt and lost-return recovery proposal

This draft persists an immutable paid packet snapshot before acknowledging an accepted payment notification, deduplicates scoped event IDs, and lists/downloads receipts for a verified server-side owner after a lost checkout return. It proves local synthetic behavior, not deployed durability or a sale.

## Implemented, disabled

`lib/recovery/entitlements.ts` binds event/receipt keys to account+mode, rechecks the current authoritative purchase before an atomic write, and preserves an existing paid snapshot under duplicate/out-of-order notifications. Owner conflicts, corrupt packets and scoped mismatches refuse delivery. Persisted ledgers validate plain maps, event hash keys/values, receipt identity/session/scope, full packet hash and structure before mutation, read or duplicate acknowledgement; malformed/corrupt storage fails closed without processing a new event. `handlers.ts` accepts raw signed events bounded at64KB/3s through an injected verifier; recovery trusts only the injected server identity. Missing/other-owner receipts use the same404. Public webhook/recovery routes always503; no environment flag enables them.

`stripe-notice.ts` uses the installed Stripe SDK's raw-body signature verification and checks event mode and any connected-account identity. Standard-account events lack an account field: the signing secret must be independently bound to the approved endpoint, and the authoritative purchase adapter must retrieve/compare the exact account and reuse existing product/version/price/quantity/currency/payment validation. A typed `VerifiedPurchase` is an internal adapter contract, never a public payment assertion.

`local-file-store.ts` is exclusively a synthetic local proof. It serializes independent instances with an exclusive filesystem lock, writes a600-mode temporary file, syncs/renames/syncs the directory, and commits only successful synchronous transactions. A stale crash lock fails closed; manual local cleanup is required. It is not production storage, and must never be wired to Vercel `/tmp`, a memory map or ephemeral instance filesystem.

Independent review identified malformed-ledger silent receipt loss, corrupt/changed-owner duplicate acknowledgement and rejected stream cancellation; all three were corrected with executable regressions. Tests cover concurrent duplicates across12storeinstances, restart/lost-return recovery, out-of-order pending/success/failure, immutable snapshots, authoritative-verification failure/retry, transactional rollback, conflicting events, cross-owner/account/mode refusal, corruption, synthetic real-SDK signatures, unsigned/tampered payload refusal, and unconditional public route closure. No real credentials, Stripe retrieval, database connection or model calls.

## Exact minimal activation packet — approval required, not executed

1. **Account/mode:** owner must supply/confirm the existing EveryMCP Stripe account ID (`acct_…`) and approved sandbox/test mode. This draft names no guessed account and reads no secret. Use a dedicated test signing secret bound to that account endpoint, not a live endpoint. Production account/mode activation remains a separate decision after sandbox acceptance.
2. **Host/storage/cost:** retain EveryMCP Vercel project under Tai. Proposed durable host is an already approved PostgreSQL service with isolated `everymcp_receipts` schema; no database/account is provisioned. Exact existing instance/region/plan and remaining capacity are unknown and must be named by the owner before wiring. Incremental spend ceiling$0; if existing capacity cannot satisfy durable serializable storage/backups, stop for an explicit named provider/price approval. No paid plan changes, external sessions or tenant access.
3. **Schema/roles/security:** [Review-only SQL](recovery-schema-proposal.sql), never applied, specifies two tables: scoped `(account_id,mode,event_id,payload_sha256)` event ledger and scoped `(account_id,mode,session_id,receipt_id,owner_key,packet,packet_sha256)` immutable paid receipt; unique account/mode/event and account/mode/session keys. Atomic SERIALIZABLE insert/read transaction with retry for serialization conflicts. Private schema, no public/anonymous grants; dedicated least-privilege server role only, no raw session IDs, packets or owner keys in logs/analytics. Encrypt storage/backups using the approved provider defaults, set bounded retention through owner approval, redact events to hashes. DDL/role grants, live DB writes and security changes have not run. A production adapter and database fault/concurrency tests remain required before activation.
4. **Verified owner:** select approved server authentication and exact Stripe-customer-to-owner binding before activation. This repo currently has no approved buyer authentication. Proposed minimal mapping is a verified email principal linked server-side to the authoritative paid checkout customer; never accept an owner/email/session supplied by the caller as proof. Authentication provider, email verification and account recovery rules require explicit approval. No new auth account or outbound email is created by this draft.
5. **Offer:** only current `everymcp-starter-kit`, version`2026-09-21`, quantity1,4900USDcents and approved legacy entitlement rules. Reuse `verifyPaidSession` / `matchesStarterEntitlement` for final authoritative proof. Do not authorize manual services, sponsorship, discounts or changed prices. Packet is snapshotted at first verified paid commit; later catalog changes do not mutate it.
6. **Sandbox scope:** after exact account/store/auth approval, separately authorize test-mode endpoint registration and one named sandbox purchase plus duplicate/out-of-order deliveries, lost-return recovery, two-owner isolation, storage failure/retry and restart. No live charge or production checkout opening is included. Preserve closed CTA until those receipts and owner recovery pass and a separate release approves activation.
7. **Rollback:** keep purchase CTA closed; unbind webhook/recovery routes or revert wiring to these503handlers. Retain already paid immutable receipts for recovery under an approved owner operator path; never delete receipts or acknowledge events before durable commit. No rollback changes Stripe prices/accounts or weakens verification. Activation code must have explicit independent review and exact hosted acceptance.
