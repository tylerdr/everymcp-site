## Implemented source

`lib/recovery/binding.ts` owns one account/mode/project binding shared by checkout, signed webhook, paid return and verified-owner recovery. `starterRecoveryEnabled = false` is a source gate: environment variables alone cannot activate it. Legacy Stripe configuration cannot open chargeable checkout. The binding requires durable store, authoritative purchase reader, account verifier, signature verifier and verified current-user identity. Missing dependencies, unsafe store privileges, failed account/store checks or absent/wrong-scoped owner refuse checkout before a session-create call. The pricing CTA also uses binding readiness.

`postgres-store.ts` uses pinned pg8.23.1, TLS certificate verification, a dedicated server login, max2connections,5sstatement/lock/connection/idle deadlines, SERIALIZABLE transactions, account/mode advisory locking and at most3attempts for serialization/deadlock/unique conflicts. It checks dedicated noninheriting/non-bypass role, forced RLS and SELECT/INSERTonly permissions on both fixed private tables, then readiness exercises actual configured account/mode INSERTs into both tables inside a rollback-only transaction (no probe committed). Grant-present but policy-denied writes refuse chargeability. These rollback-only INSERTs are database writes requiring approved sandbox write permission; they are NOT the earlier catalog-only/read-only preflight. It validates persisted event keys/hashes before map assignment and discards failed connections. It scopes every parameterized read/insert, and refuses mutation/deletion, corrupt receipt state or failed commit before acknowledgement. Fake-client tests are not actual PostgreSQL durability/concurrency proof. Catalog ACL/capacity preflight, exact RLS policy review and actual rollback/restart proof remain prerequisites.

`owner.ts` verifies only the bearer caller's own current Supabase user at the fixed project Auth endpoint, requiring confirmed email and nonanonymous valid user ID. Responses are bounded64KB and requests5s. No admin/service_role/auth.users lookup, signup or mail. Opaque owner keys bind product/account/mode/project/userID. Checkout stamps this server principal and verified email; body/query owner/email cannot grant rights. Public buyer sign-in/verified-owner onboarding is not yet approved or exposed by this backend-only draft.

`purchaseReader` reuses authoritative Stripe product/version/currency/quantity/payment checks and verifies session/mode/owner/project. Signed event and verified return share atomic immutable first-paid packet storage; existing snapshots are read without rebuilding a changed catalog. Recovery lists only verified owner's receipt IDs/hashes and downloads the stored packet; wrong-owner/missing both404. Historic ownerless sessions retain verified session-bearer delivery and are never attached to a newly claimed login. While the new binding is disabled, only historical unbound return-link rights use the old builder path; sessions bearing any owner/auth-project/pricing-policy field refuse regeneration with503/retry if binding/storage is unavailable. This rollback preserves immutable new-contract snapshots. Historical fallback does not claim durable lost-return recovery.

New checkout remains4900USDcents, quantity1, current starterSKU/version, no promotions, strict `usd4900-no-discount-v1` metadata. Entitlement reconciles collected total =4900−discount+tax, shipping0; new policy requires discount0 and accepts legitimate tax. Historical sessions without the new policy can retain already-paid discounted rights if totals/product/payment reconcile; this is continuity, not permission for future discounts. Missing/negative/mismatched totals, unpaid sessions, unknown policy or scope/product mismatch refuse entitlement. Manual consulting/sponsorship and subscriptions remain outside launch.

Core `entitlements.ts` validates immutable ledgers, scoped identity, ordered complete packet and full SHA256 before mutation, read or duplicate acknowledgement. Raw signed events are bounded64KB/3s; duplicate/out-of-order failures cannot revoke an existing paid snapshot. `local-file-store.ts` remains synthetic-local only, never Vercel/tmp production storage. No probability/scoring/publication/MCP evaluation change.
