# Frozen compatibility evidence contract v1

This candidate implements **only the evidence-contract improvement**, not a profile-to-impact classifier. The current architecture retains source body hashes, complete section hashes and deliberately bounded previews; it cannot reconstruct complete passages absent from those previews. A separately supplied raw body must match an already verified capture. Without it the gate abstains. No collector, receipt schema, storage, route, report renderer, entitlement or retention policy was changed.

The machine-readable contract is [compatibility-evidence-contract-v1.json](compatibility-evidence-contract-v1.json); the pure implementation is `lib/monitoring/compatibility-evidence.ts`. Its source/contract hashes are frozen in the accompanying receipt before any fresh held-out evaluation. The prior private manual-card experiment and original artifacts are preserved, not copied into these tests or used as algorithmic acceptance. The new fixtures contain unrelated fictional routing documents and no experiment case IDs or expected impact labels.

## Trust and evidence boundary

A trusted caller must first establish current owner/rights and load the canonical comparison subject, full inventory snapshot and independently selected receipt IDs. This function grants no access and is not a public endpoint. It accepts strict service-v1/v2 capture originals under their original signature and integrity policies; Python/GitHub and Node receipt origins are not silently reinterpreted. The original source payload and job must match the exact scope, owner, watchlist/version, slugs, full canonical URL cohort and inventory. The pair must contain distinct ordered executions/nonces within90days. It is not asserted to be adjacent or globally latest.

Every selected source in both captures must have an actual `checked_this_run`, complete HTTP200 observation and captured projection inside its execution interval. The whole report must satisfy the existing service capture window: check mode, no dry-run sources, at most two checked sources, one robots request and 30,000ms reported request duration. Checked observations outside the canonical job and uncounted current observations are refused. The before observation must be fresh at its completion; the after observation must be fresh at explicit `asOf`, using the existing `isDue` calendar policy (one day for priority sources, otherwise seven). Cached/304, missing, partial, stale, unsupported or unverified sources abstain. This is completeness of the service-recorded response within the declared canonical scope, not a claim that the customer's true dependency list or all runtime behavior is covered.

Full-body supplements are transient inputs: at most16KiB per document and64KiB total new material including profile/quotation/URL metadata. Existing signed originals remain under their existing receipt/source limits; the supplement cap does not shrink or reinterpret a full-catalog receipt. The profile has at most12 named workflow steps, bounded descriptions, source URLs only from the canonical cohort, and an8KiB cap. Only its digest and bounded step identifiers are returned, not arbitrary profile prose.

The implementation hashes original bytes before strict UTF8 decoding, checks signed body length/hash and recomputes the entire retained projection from the supplement. Preview truncation is allowed because complete source bytes and section hashes are present; missing or incomplete extraction is not. Initially only plain text and Markdown are supported. HTML is explicitly unsupported because literal HTML/script/attribute strings are not necessarily rendered documentation. No content conversion or reference substitution is performed.

Up to eight requested quotes must match exact nonempty UTF8 byte spans, each at most160 Unicode characters. All emitted occurrences across both phases and all step links count against the existing **24-word budget per source URL**. The gate never resets that budget per finding, step or phase. The returned citation binds source URL, observation date, original receipt, source payload, body hash and observation pointer. Step links are **profile declarations, not verified relevance**. No free-form finding, migration assertion or caller paid flag is accepted as authority.

If any selected document or quote fails, the whole request returns `abstain` with no quotes. A successful result means only `ready_for_document_review`; its raw-byte comparison can be changed/unchanged while `documentContractChange` and `potentialWorkflowImpact` stay `not_assessed`, `runtimeCompatibility` stays `unverified`, and `rightsGranted` stays false. Neither a verified signature nor unchanged bytes proves compatibility. Service signatures still only endorse assertions by trusted service credential holders; compromised holders or code can lie about fetching/time/completeness.

## What remains unsupported

Current retained originals alone cannot meet this new input contract. No new body collector, source-fetch fallback, supplement persistence, public route, semantic parser, model call or impact algorithm is wired. A later owner must separately decide and review where complete bounded bytes can be provided lawfully and securely, how to bind any supplement custody to current rights, and whether/how useful impact inferences can be derived. Larger documents, HTML and dynamic/linked evidence abstain in this first contract. A source's supplement availability is not inferred from a READY build.

Before further implementation, use fresh held-out fixtures to test evidence admission and abstention under this exact frozen contract; impact-classification grading would be premature because no classifier exists. Any new format, body limit, retention, supported syntax or impact claim requires an explicitly versioned review rather than changing the meaning of existing originals. Namespace/native restrictions, PR30/33/35 custody, disabled paid activation and the unapproved90-day recovery alternative remain intact.
