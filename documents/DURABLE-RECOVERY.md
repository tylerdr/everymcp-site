# Disabled durable receipt and lost-return recovery proposal

This draft persists an immutable paid packet snapshot before acknowledging an accepted payment notification, deduplicates scoped event IDs, and lists/downloads receipts for a verified server-side owner after a lost checkout return. It proves local synthetic behavior, not deployed durability or a sale.

## Implemented, disabled

`lib/recovery/entitlements.ts` binds event/receipt keys to account+mode, rechecks the current authoritative purchase before an atomic write, and preserves an existing paid snapshot under duplicate/out-of-order notifications. Owner conflicts, corrupt packets and scoped mismatches refuse delivery. Persisted ledgers validate plain maps, event hash keys/values, receipt identity/session/scope, full packet hash and structure before mutation, read or duplicate acknowledgement; malformed/corrupt storage fails closed without processing a new event. `handlers.ts` accepts raw signed events bounded at64KB/3s through an injected verifier; recovery trusts only the injected server identity. Missing/other-owner receipts use the same404. Public webhook/recovery routes always503; no environment flag enables them.

`stripe-notice.ts` uses the installed Stripe SDK's raw-body signature verification and checks event mode and any connected-account identity. Standard-account events lack an account field: the signing secret must be independently bound to the approved endpoint, and the authoritative purchase adapter must retrieve/compare the exact account and reuse existing product/version/price/quantity/currency/payment validation. A typed `VerifiedPurchase` is an internal adapter contract, never a public payment assertion.

`local-file-store.ts` is exclusively a synthetic local proof. It serializes independent instances with an exclusive filesystem lock, writes a600-mode temporary file, syncs/renames/syncs the directory, and commits only successful synchronous transactions. A stale crash lock fails closed; manual local cleanup is required. It is not production storage, and must never be wired to Vercel `/tmp`, a memory map or ephemeral instance filesystem.

Independent review identified malformed-ledger silent receipt loss, corrupt/changed-owner duplicate acknowledgement and rejected stream cancellation; all three were corrected with executable regressions. Tests cover concurrent duplicates across12storeinstances, restart/lost-return recovery, out-of-order pending/success/failure, immutable snapshots, authoritative-verification failure/retry, transactional rollback, conflicting events, cross-owner/account/mode refusal, corruption, synthetic real-SDK signatures, unsigned/tampered payload refusal, and unconditional public route closure. No real credentials, Stripe retrieval, database connection or model calls.
